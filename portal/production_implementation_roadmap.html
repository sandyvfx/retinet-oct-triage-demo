Production Implementation Roadmap

This roadmap converts the static POC into production workstreams. No production backend is implemented in this phase.

Stage / objectiveRequired backend componentsRequired data inputsValidation gateOpen risksDone condition
Stage 1 - Secure upload and case intake

Accept de-identified scan intake and create review cases with case_hash identifiers.

Upload API, intake validation, file quarantine, case queue service.OCT images, native scan files, modality tags, eye side, redacted metadata.Uploads are accepted only after file type, size, metadata, and malware checks.File variability, incomplete metadata, privacy controls not yet productionized.Case intake creates review-ready records without PHI in public views.
Stage 2 - Native OCT file conversion service

Convert supported native OCT files into normalized B-scan sequences and manifests.

Conversion worker, vendor format registry, conversion manifest store.Native/vendor OCT file data, conversion rules, sample validation packs.Each vendor format requires sample validation and manifest reconciliation.Vendor format variability, parser drift, unsupported metadata fields.Converted B-scans and redacted manifests are available for review workflow.
Stage 3 - OCT image/metadata normalization

Normalize image dimensions, scan metadata, and biomarker-ready derived fields.

Image normalization worker, metadata redaction service, quality checks.Converted B-scans, OCT image data, redacted scan attributes.Quality metrics and redaction checks pass before model or review routing.Device distribution shift, inconsistent acquisition settings, missing metadata.Normalized images and minimal metadata are available for downstream review.
Stage 4 - Doctor review workspace

Provide a production review console for biomarkers, heatmaps, notes, and sign-off.

Review UI, note service, report status workflow, override workflow.B-scans, biomarker outputs, AI review-support outputs, doctor notes.Override reason and sign-off controls are enforced before export.Clinical workflow fit, reviewer burden, unclear escalation criteria.Doctor review required is enforced for every exportable case.
Stage 5 - BYOM model connector service

Let the backend AI team plug in model endpoints through a stable contract.

Model Connector Contract, task router, request validator, response validator.Task selection, normalized scan references, biomarkers, model metadata.Responses must include safety flags and not_diagnosis metadata.Endpoint instability, incompatible schemas, incomplete uncertainty reporting.Model outputs are ingested as review-support metadata only.
Stage 6 - Model registry and evidence registry

Track model versions, metrics, evidence packages, and artifact lineage.

Model registry, evidence registry, artifact manifest store.Model version, metric summaries, model cards, validation evidence.Registry entries require version, owner, evidence boundary, and approval status.Unversioned models, stale evidence, unclear ownership.Every model output links to a registered model version and evidence record.
Stage 7 - Similarity search / embedding index

Support reviewer context with KNN and hybrid similarity search.

Embedding generator, vector index, structured biomarker search.Image embeddings, structured biomarkers, redacted report text.Similarity results are labeled reviewer context only, not diagnosis.Embedding drift, misleading neighbors, insufficient auditability.Similar cases use case_hash only and display context boundaries.
Stage 8 - Report draft/export/sign-off workflow

Generate draft exports and enforce doctor sign-off before final output.

Report generator, export templates, signing workflow, export audit log.Doctor impression, review status, biomarkers, safe AI metadata.Export requires doctor sign-off and no PHI in public demo assets.Template mismatch, missing sign-off, overstatement in report wording.Draft and signed export states are distinct and auditable.
Stage 9 - Audit logging and role-based access

Create an access-controlled audit trail for review, model, and export events.

RBAC layer, audit event log, event hash chain, admin review tools.User roles, case events, model events, export events.Access controls and audit events pass security review.Permission gaps, incomplete audit capture, operational policy gaps.Every sensitive action has an auditable event and role boundary.
Stage 10 - External validation and clinical review protocol

Evaluate performance, safety, calibration, and workflow fit before production use.

External test protocol, ophthalmologist review workflow, calibration reports.De-identified client data, external test set, reviewer labels, model outputs.External validation and clinical review protocol are completed and documented.Clinical validation not performed, public dataset bias, regulatory uncertainty.Production readiness is reviewed with documented limitations and gates.
