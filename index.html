For Medical Officer / Diagnostic Center & Doctor

A review-support workflow for OCT/macula case intake, doctor-led review, report export, and optic nerve/glaucoma metadata visualization.

1. Upload / View OCT Images

Upload or review de-identified OCT and retinal images inside a case-based workflow.

2. Native OCT / Vendor File Conversion

Production roadmap supports native vendor OCT conversion into normalized B-scan and metadata views.

3. Macula OCT Triage Workflow

Public Kermany OCT evidence demonstrates experimental macula-category model evidence for CNV, DME, DRUSEN, and NORMAL classes.

4. Glaucoma / Optic Nerve Report Visualization

ORIGA CDR/ExpCDR evidence is shown as fundus optic-nerve metadata only, not OCT glaucoma.

5. Heatmap / Explainability Layer

Visual explanation and heatmap layer planned for doctor review support and audit discussion.

6. Doctor Review Workflow

Doctor-led notes, impression, override reason, and sign-off boundary before report export.

7. Case Dashboard

Case-level view for scan status, AI evidence summary, review state, and doctor action.

8. Report Export / Journal Notes / Medication History

Future workflow can attach report export, journal notes history, and medication history to the review case.

For Backend ML / AI Team

A technical handoff layer for model integration, evidence tracking, validation, and safe review-support outputs.

1. Bring-Your-Own-Model Integration

Plug backend AI models into a stable request/response contract without changing the doctor workflow.

2. Model Connector Contract

Defines expected inputs, outputs, uncertainty, safety flags, and review-support boundaries.

3. Evidence / Model Registry

Track model versions, metrics, model cards, validation summaries, and artifact lineage.

4. KNN / Hybrid Similarity Search

Future reviewer context layer using embeddings, structured biomarkers, and case_hash-based retrieval.

5. SDK / CLI Operations

Support batch validation, evidence generation, and backend AI team workflows through scripted operations.

6. Validation & Audit Layer

Preserve dataset evidence, external validation gates, calibration review, and audit history before production claims.

7. Privacy / PHI Boundary

Public demo exposes no PHI or raw vendor files; production requires secure storage, RBAC, retention, and audit logs.

8. Deployment Boundary

Static POC only; no production backend, auth, database writes, model inference service, or checkpoint loading is implemented here.
